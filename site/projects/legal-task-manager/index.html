Case study

Legal Task Manager

An Arabic-first task manager and contracts register for a legal team that looks after leases across several shopping centres: who owns each piece of work, what is due today, and which contract is still missing a signature. Self-hosted on the client's own server, in production since October 2026.

The problem

The team's work lived in email threads and a shared spreadsheet. Nobody could answer three simple questions without asking around: what is still open, who is responsible for it, and what has to be done today. The contract register was a separate workbook, so a lease missing a stamp or a tenant document was found only when someone went looking.

An earlier plan had been a shared document system with in-browser editing. After walking through the team's real requirements, it was dropped: they needed a task manager they would actually open every morning, in Arabic, and a register that matched the workbook they already trusted.

Approach

One screen that answers "what now?"

The home view sorts every open task into urgent: due today (overdue first, then due today or flagged by hand), upcoming and a collapsed completed list, with counters in the header and one chip per file. Work is organised the way the team already thought about it: file (a mall), then topic (a tenant brand), then task. Other views group the same tasks by topic or by person.

Rules in the database, not the widgets

Lawyers see only the files they are members of, create tasks only for themselves and edit only their own; managers assign and review; admins manage accounts. All of it is enforced by PostgreSQL Row Level Security and triggers, so it holds even if the API is called directly. "Urgent" and "overdue" are computed in the database on the local date, so every screen and every export agrees on what today means.

An audit trail nobody has to remember to write

Every change to a task writes its own history row from a trigger, and the same triggers write the notifications: assigned to you, status or due date changed, someone posted an update. Realtime is used only as a signal to re-read, so a missed message can never leave a screen showing stale data.

A contracts register that matches the workbook

Leases, annexes and storage contracts hang together, and each contract shows its values after its active annexes, with a note saying which annex changed what. A checklist tracks missing signatures and stamps per contract and documents per tenant. Whatever the filtered list shows exports to an Excel register laid out like the team's own workbook, or prints on A3. Both are generated entirely in the browser.

Arabic first

The interface is right-to-left with Arabic-Indic digits by default. Each stored text field detects its own direction, so a title typed in English sits correctly inside an Arabic layout. Search normalises Arabic spelling (أ/ا, ة/ه, ى/ي and diacritics) and uses trigram matching in PostgreSQL.

The hard parts

Self-hosting on a LAN with no public endpoint. Client data stays on-premises: the system runs in an Ubuntu VM on the client's Windows Server, with Supabase in Docker behind Nginx on a single origin. Every database port is bound to localhost and only the API paths are proxied. Until the internal domain was ready, HTTPS used a private certificate authority constrained to one address. Every setup step is written into a runbook so the server can be rebuilt from scratch.

An export that broke only in production. The register export worked locally and returned 502 on the server. The query echoed hundreds of contract ids in a response header that outgrew Nginx's proxy buffer. The fix was twofold: send ids in small chunks and size the buffers deliberately, then check the export again against production.

"Effective" values without drift. An annex can extend a lease, move its area or transfer it to another tenant. Computing the effective values in one database view, rather than in the app, keeps the list, the drawer and the Excel export from ever disagreeing.

Try it

The demo is the real application. Only its data layer is swapped for an in-memory store that re-states the database rules. Use the bar at the bottom to switch between the manager, a lawyer and the admin. Create a task for a lawyer as the manager, then switch to the lawyer to see it arrive in the notification bell. Open Contracts to see annexes, the missing-items checklist and the Excel export. The language toggle flips the whole app to Arabic and right-to-left.
